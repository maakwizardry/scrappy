Scrappy · CA Campaign

Home-cleaning outreach pipeline — Canada-wide

The original campaign, and the only one with two ways to run it: a set of continuous background workers, and a manual Express API that does the same three jobs one call at a time. Both read and write the same MySQL tables, but the final step — turning a lead into an email — is implemented twice, in two different ways.

01 Scrape scrapeWorker.js

For every keyword × location pair, pages through YellowPages.ca search results up to MAX_PAGES = 30, stopping early once a page comes back empty or the site blocks the request. Parses .listing cards for name / phone / address, unwraps YP's redirect= website links, and dedupes via businessExists(name, phone) before insert.

Checkpoint progress.json — resumable {keywordIndex, locationIndex}

02 Enrich worker.js

Continuous queue loop (poll every 5s, 30s idle, 10s on error) — identical logic to the USA enrichment worker, just without the state filter. No-website rows get heuristic pain-point tags; a website first runs validateUrl() to catch dead/parked/social-redirect domains, then performEnrichment() scrapes CMS, SSL, contact page, testimonials, and a lead score.

Uses urlValidator.js enrichment.js → fetchPage.js

03 Booking outreach bookingOutreach.js

Continuous queue loop (5s after success for rate-limiting, 30s idle, 10s on error). Pulls one qualified cleaning-service lead nationwide, creates a provider via the booking API, picks 1 of 3 message templates at random, and assembles a 3-paragraph email with the provider's booking link, a Calendly CTA, and a fixed signature block.

Uses bookingApiClient.js — retry w/ backoff, 2s pacing
External API POST letsbook.maakhq.com/api/providers → provider + templates
Static link calendly.com/workwithmaak — embedded in email copy only

Lane B Manual HTTP API server.js — Express on :3000, the one process PM2 actually keeps alive (ecosystem app "yp-scraper"). Same three jobs, triggered per-call instead of looping.
POST /scrape { keyword, location }

One-shot version of scrapeWorker.js: scrapes a single YellowPages.ca results page for the given pair and inserts every listing directly — no dedupe check, no pagination.

Writes businesses — INSERT
POST /enrich

Pops one enriched = 0 row off the same queue worker.js drains, and runs performEnrichment() directly — skips urlValidator.js, so it doesn't pre-classify dead/parked domains before scraping them.

Writes business_enrichment — INSERT, businesses.enriched — UPDATE
POST /analyze analyze.js — analyzeNext()

The legacy email path, and the one place this pipeline calls an LLM. Builds a niche-specific prompt from the business + its enrichment row, sends it to gpt-4o-mini, and parses back a bespoke { subject, body } — one email written from scratch per lead, instead of a template pick.

External API OpenAI chat.completions — model gpt-4o-mini

→ Output — two flags, two authors

business_analysis ends up with rows written by two different generators: analyzed = 1 rows came from a human calling POST /analyze and an LLM prompt; booking_analyzed = 1 rows came from the automated bookingOutreach.js loop and a fixed template. Nothing in ca/ sends either email automatically — dispatch is a manual or external step outside this pipeline.
